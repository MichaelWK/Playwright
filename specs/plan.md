# Test Plan: Landing Page (create-next-app scaffold)

**Application under test:** http://localhost:3000/
**State at time of planning:** Unmodified `create-next-app` starter — single route (`/`), no forms, auth, or backend. This plan covers the current UI surface; extend it once real product features land.
**Note on method:** Live-browser MCP tools (`playwright-test/*`) were not available in this session, so this plan was derived from reading `app/page.tsx` / `app/layout.tsx` directly rather than an interactive browser exploration. Steps should be spot-checked against a live snapshot before the generator agent implements them.

---

### 1. Page Metadata & Branding

**Seed:** `e2e/seed.spec.ts` (navigate to `/`)

#### 1.1 Page loads with correct title and description

**Steps:**

1. Navigate to `/`
2. Read the document title
3. Read the `<meta name="description">` content

**Expected:**

- Title contains "Create Next App"
- Description equals "Generated by create next app"

#### 1.2 Primary heading and instructional copy are visible

**Steps:**

1. Navigate to `/`
2. Locate the heading containing "Create Next App"
3. Locate the heading/paragraph instructing the user to edit `page.tsx`, including the inline `page.tsx` code snippet
4. Locate the descriptive paragraph mentioning "Templates" and "Learning"

**Expected:**

- All elements are visible in the main content area
- The inline `page.tsx` text is rendered inside a `<code>` element

#### 1.3 (Negative/edge) Heading hierarchy

**Steps:**

1. Navigate to `/`
2. Query all `<h1>` elements on the page

**Expected / known issue to confirm:** The page currently renders **two** `<h1>` elements ("Create Next App" and the "To get started..." copy). Flag as an accessibility finding if confirmed — a page should generally have a single `<h1>`. Record actual vs. expected rather than failing silently.

## Out of scope / follow-ups

- `e2e/example.spec.ts` currently contains tests that navigate to and assert against **playwright.dev** and **vercel.com**'s own UI (their search widget, their import form). These test third-party sites, not this application — recommend deleting or replacing them; they are unrelated to this plan and will be flaky against unrelated deploys.
- No forms, authentication, data persistence, or API routes exist yet — once real product features are added (beyond the create-next-app scaffold), this plan should be extended with functional/edge-case/error-handling scenarios per those features.
